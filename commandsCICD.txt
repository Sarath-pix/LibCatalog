GENERAL CI/CD EXAM TEMPLATE — SOURCE FILES FIRST, COMMANDS AFTER
==================================================================

HOW TO USE THIS FILE
--------------------
This is a reusable starter template for a simple Python Flask web API.
For another exam application, make small changes to the app name, routes/data,
test names, Docker image name, port, and Kubernetes resource names.

You do not need to use every file if your exam asks for fewer stages.
Read the exam question first. Do not copy secrets or passwords into any source file.

Suggested project structure:

your-project/
├── app.py
├── requirements.txt
├── test_app.py
├── Dockerfile
├── .dockerignore
├── .gitignore
├── .github/
│   └── workflows/
│       └── pipeline.yml
└── k8s/
    └── deployment.yaml


PART 1 — SOURCE FILES
=====================

FILE 1: app.py
--------------
A small Flask API with a home endpoint, sample data endpoint, and health endpoint.
Change the sample data and route names to suit the application in your exam.

----- START app.py -----
from flask import Flask, jsonify

app = Flask(__name__)

# Replace this sample data with the data for your application.
items = [
    {"id": 1, "name": "Item One"},
    {"id": 2, "name": "Item Two"},
    {"id": 3, "name": "Item Three"},
]


@app.route("/")
def home():
    return jsonify({
        "message": "Application is running",
        "items_count": len(items),
        "endpoints": ["/", "/items", "/health"]
    })


@app.route("/items")
def get_items():
    return jsonify(items)


@app.route("/health")
def health():
    return jsonify({"status": "healthy"})


if __name__ == "__main__":
    # Use 0.0.0.0 so the app can be reached from Docker/Kubernetes.
    app.run(host="0.0.0.0", port=5000)
----- END app.py -----

FILE 3: test_app.py
-------------------
Basic automated tests. Update the expected message/routes if you change app.py.

----- START test_app.py -----
from app import app


def test_home():
    client = app.test_client()
    response = client.get("/")
    assert response.status_code == 200
    data = response.get_json()
    assert data["message"] == "Application is running"


def test_items():
    client = app.test_client()
    response = client.get("/items")
    assert response.status_code == 200
    assert isinstance(response.get_json(), list)


def test_health():
    client = app.test_client()
    response = client.get("/health")
    assert response.status_code == 200
    assert response.get_json()["status"] == "healthy"
----- END test_app.py -----

FILE 7: .github/workflows/pipeline.yml
--------------------------------------
This workflow runs tests on pushes and pull requests. On a push to main, it then
builds and pushes the Docker image to Docker Hub.

Before using it:
- Create GitHub repository secrets named DOCKERHUB_USERNAME and DOCKERHUB_TOKEN.
- DOCKERHUB_TOKEN must be a Docker Hub access token with permission to push images.
- Change YOUR_DOCKERHUB_USERNAME and YOUR_APP_IMAGE to your real Docker Hub username/image.
- The example assumes Python 3.12, requirements.txt, pytest, and a Dockerfile in the project root.

----- START .github/workflows/pipeline.yml -----
name: CI CD Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

permissions:
  contents: read

jobs:
  test:
    name: Run Tests
    runs-on: ubuntu-latest

    steps:
      - name: Checkout source code
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt

      - name: Run tests
        run: python -m pytest -v

  build-and-push:
    name: Build and Push Docker Image
    needs: test
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest

    steps:
      - name: Checkout source code
        uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}

      - name: Build and push image
        uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: YOUR_DOCKERHUB_USERNAME/YOUR_APP_IMAGE:latest
----- END .github/workflows/pipeline.yml -----


FILE 8: k8s/deployment.yaml
---------------------------
Creates two replicas and a service. Change the image, names, and ports as needed.
The app in this template listens on container port 5000.

----- START k8s/deployment.yaml -----
apiVersion: apps/v1
kind: Deployment
metadata:
  name: sample-app
spec:
  replicas: 2
  selector:
    matchLabels:
      app: sample-app
  template:
    metadata:
      labels:
        app: sample-app
    spec:
      containers:
        - name: sample-app
          image: YOUR_DOCKERHUB_USERNAME/YOUR_APP_IMAGE:latest
          ports:
            - containerPort: 5000
          readinessProbe:
            httpGet:
              path: /health
              port: 5000
            initialDelaySeconds: 5
            periodSeconds: 10
---
apiVersion: v1
kind: Service
metadata:
  name: sample-app-service
spec:
  type: NodePort
  selector:
    app: sample-app
  ports:
    - port: 5000
      targetPort: 5000
      nodePort: 30080
----- END k8s/deployment.yaml -----


# PART 2 — WINDOWS COMMANDS (STEP BY STEP)

All commands below are for Windows PowerShell in VS Code.

## STEP 1 — OPEN YOUR PROJECT

Open your project folder in VS Code.

Open Terminal → New Terminal.

Check the current folder and files:

Get-Location

Get-ChildItem


## STEP 2 — INSTALL PYTHON PACKAGES

Create a virtual environment:

py -m venv .venv

Activate it:

.\.venv\Scripts\Activate.ps1

If activation is blocked, run:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

.\.venv\Scripts\Activate.ps1

Install the required packages:

py -m pip install -r requirements.txt


## STEP 3 — RUN THE APP AND TEST IT

Run the tests:

py -m pytest -v

Start the application:

py app.py

Keep this terminal open. Open another terminal and test:

curl.exe http://localhost:5000/

curl.exe http://localhost:5000/health

Stop the app using Ctrl + C.


## STEP 4 — UPLOAD THE PROJECT TO GITHUB

Check Git:

git status

If Git is not initialized yet, run:

git init

git branch -M main

git add .

git commit -m "Initial commit"

Create an empty repository on GitHub. Connect it using your repository URL:

git remote add origin https://github.com/USERNAME/REPOSITORY.git

git push -u origin main

For later changes, use:

git add .

git commit -m "Update application"

git push

If a remote already exists, do not add it again.


## STEP 5 — SET UP GITHUB ACTIONS

Create the workflow folder and file:

New-Item -ItemType Directory -Force .github\workflows

New-Item -ItemType File -Force .github\workflows\pipeline.yml

Open pipeline.yml in VS Code and paste FILE 7 from Part 1.

Replace the Docker Hub image placeholder with your actual username and image name.

Save the file and run:

py -m pytest -v

git add .

git commit -m "Add GitHub Actions workflow"

git push

Open your GitHub repository → Actions and check whether the workflow passes.


## STEP 6 — BUILD THE DOCKER IMAGE

Start Docker Desktop and wait until it is running.

Build the image. Replace APP_NAME with your app name:

docker build -t APP_NAME:latest .

Check the image:

docker images


## STEP 7 — RUN THE DOCKER CONTAINER

Run the container:

docker run -d --name APP_NAME-container -p 5001:5000 APP_NAME:latest

Check that it is running:

docker ps

docker logs APP_NAME-container

Test the app:

curl.exe http://localhost:5001/

curl.exe http://localhost:5001/health

If the container name is already in use, remove the old container:

docker rm -f APP_NAME-container


## STEP 8 — PUSH THE IMAGE TO DOCKER HUB

Log in:

docker login

Tag your image:

docker tag APP_NAME:latest DOCKERHUB_USERNAME/APP_NAME:latest

Push it:

docker push DOCKERHUB_USERNAME/APP_NAME:latest

Replace the placeholders with your actual app name and Docker Hub username.


## STEP 9 — AUTOMATE DOCKER PUSHING

In GitHub, open:

Repository → Settings → Secrets and variables → Actions

Create these two secrets:

DOCKERHUB_USERNAME — your Docker Hub username

DOCKERHUB_TOKEN — your Docker Hub access token

In FILE 7, make sure the image tag matches your Docker Hub repository.

Push your updated workflow:

git add .

git commit -m "Automate Docker image publishing"

git push

Open GitHub → Actions and confirm that the tests and Docker image publishing succeed.


## STEP 10 — DEPLOY TO KUBERNETES

Make sure Kubernetes is enabled in Docker Desktop.

Check the cluster:

kubectl get nodes

Create the Kubernetes folder and file:

New-Item -ItemType Directory -Force k8s

New-Item -ItemType File -Force k8s\deployment.yaml

Open k8s\deployment.yaml and paste FILE 8 from Part 1.

Replace the Docker Hub image placeholder with your actual image.

Deploy the application:

kubectl apply -f k8s/deployment.yaml

Check the deployment:

kubectl get pods

kubectl get deployments

kubectl get services

If a pod is not running, check its logs:

kubectl logs deployment/sample-app

To access the app locally, run:

kubectl port-forward service/sample-app-service 8080:5000

Keep that terminal open. In another terminal, test:

curl.exe http://localhost:8080/

curl.exe http://localhost:8080/health

Stop port forwarding with Ctrl + C.


## STEP 11 — SAVE YOUR FINAL CHANGES TO GITHUB

After changing or adding files, run:

git status

git add .

git commit -m "Add final CI/CD and Kubernetes files"

git push

If Git says there is nothing to commit, no new changes need saving.


## QUICK EXAM ORDER

Remember this order:

1. APP — Run the application.
2. TEST — Check that tests pass.
3. GITHUB — Upload the code.
4. CI — Set up GitHub Actions.
5. DOCKER — Build and run the container.
6. HUB — Push the image to Docker Hub.
7. KUBERNETES — Deploy and test, if required.

Important: Use only the steps required by your exam question. Replace sample names and ports with the values used in your application.

QUICK TROUBLESHOOTING
=====================
Tests fail:
python -m pytest -v

Container stopped or crashed:
docker ps -a
docker logs APP_NAME-container

Docker build fails:
Check that Dockerfile exists, is not empty, and its CMD matches the app's entry file.

Docker Hub says 401 or insufficient scopes:
Check the username and update the GitHub DOCKERHUB_TOKEN secret with a token that can
read and write repositories. Then rerun the failed workflow.

Pods are not ready:
kubectl get pods
kubectl describe pod POD_NAME
kubectl logs deployment/sample-app

Service cannot be reached:
kubectl get services
kubectl get endpoints sample-app-service
Try the port-forward command shown above.
